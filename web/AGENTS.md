# Web rules (React 19 + TypeScript + Vite)

Stack pins in `web/package.json` (React 19.3, TS 7.0, Vite 8.3, Vitest 5).

1. Function components + hooks only; no class components.
2. Call the backend only via relative `/api/v1/...` through `src/api.ts` (Vite proxy in dev, Nginx in compose). Never hardcode `localhost:8080`.
3. Booking flow: dealership → vehicle → service → date → slots → confirm. Show each unavailable slot's `reason` through `slotReasonText` (`labels.ts`); add a label when the API adds a reason code.
4. Send `Idempotency-Key` on `POST /appointments`; keep the same key until the selected slot changes.
5. Disable Confirm while the request is in flight (`useAsyncAction`).
6. After book/cancel/lifecycle actions, refetch availability + schedule. Live updates come from WebSocket `/api/v1/ws/dispatch` via `useLiveEvents` (opens with a `POST /auth/ws-ticket` ticket, never the access token): refetch on `APPOINTMENT_*` (`LIVE_APPT_EVENTS` in `live.ts`), `AVAILABILITY_CHANGED`, `CONFIG_UPDATED` (the catalog, plus — silently, keeping a pick still offered — the grid and the first-available list when it concerns the view: `configRefresh`; a window-less `AVAILABILITY_CHANGED`, sent for a technician change, re-reads both too; a windowed one re-reads the first-available list, and the grid only when the window is on the form's day in the dealership's zone: `availabilityRefresh`); the board reloads only for its dealership-day or an appointment it shows (`boardAffected`); bursts coalesce with a 1 s max wait; drop notices whose `version` is not newer; resync after every reconnect. Requests send this tab's in-memory access token (`auth.ts`); the socket follows the session's `key`, so a token refresh keeps it open.
7. Type every API payload in `src/types.ts`; no `any`. Numeric enums (`Status`, `Bay`, `Skill`, `SkillLevel`, `Role`, `EventType`, `AggregateType`) must mirror `backend/internal/domain`; compare against the constants, never bare numbers or names (WebSocket `type` and `ConfigNotice.entity` are codes too).
8. Vitest for pure helpers (`*.test.ts`); Testing Library + jsdom for components and hooks (`*.test.tsx`, setup in `src/testSetup.ts`).
9. Verify with `npx tsc --noEmit && npm test` (and `npm run build` before done).
10. Mutations on appointments and admin config send the shown `version` as `If-Match`; on 412 reload and tell the user instead of overwriting.
11. Session auth (`auth.ts`, `useSession.ts`, `api.ts`): the access token and user live in memory only — never write them to `localStorage`/`sessionStorage` (legacy `uss.token`/`uss.user` keys are deleted at startup). The HttpOnly `uss_refresh` cookie (Path `/api/v1/auth`) restores a reload: boot calls `POST /auth/refresh` (`credentials: "same-origin"`, `X-Requested-With: fetch`) and shows "Checking your session…" until it answers. Refresh ~60 s before `expiresAt` (`REFRESH_AHEAD_MS`); a 401 from any endpoint but login/register/refresh/logout gets one shared refresh (`refreshSession`, one in-flight promise, `navigator.locks` "uss-auth-refresh" across tabs) and one retry, a second 401 or a refused refresh signs out with the expiry notice; a request is never replayed as another account. Tabs sync over `BroadcastChannel("uss-auth")` (`{type:"session",…}` after login/refresh, `{type:"signed-out"}` after logout): same account → adopt silently, another → reset the view with the "signed in as X in another tab" notice. Logout = clear memory + view at once and broadcast `{type:"signing-out"}` (other tabs hide everything, adopt nothing), then `POST /auth/logout` (Bearer + cookie + `X-Requested-With`, 10 s timeout) retried in rounds (`SIGN_OUT_RETRY_DELAYS_MS`, again on `online` / "Try again") until 204 or 401; only then `{type:"signed-out"}` and a clean signed-out view. While unconfirmed (sessionStorage flag `uss.signout-pending`, no credential) the tab never refreshes or adopts a session, also after a reload; a login replaces it. A refresh lost to the network/timeout/5xx is retried once immediately (inside the server's reuse grace) before any backoff. The expiry warning uses `sessionExpiresAt` (absolute end), not the access token's expiry. Key per-session effects on `session.key`, never on `session.token` (it rotates every refresh).
