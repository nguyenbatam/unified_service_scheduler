# Operations notes

Details kept out of the README: network exposure, metrics, client IP handling, compression and caching, the web UI's auth model, and the WebSocket endpoint.

## Network exposure

Only the gateway (8080) and the web UI (8081) listen on every interface; Postgres, Redis (no password), Kafka, Prometheus, Grafana (`admin`/`admin`, anonymous viewers) and the two backends are published on 127.0.0.1 only. The gateway's access log records the method and path, never the query string (customer search text, VINs, WebSocket tickets).

## Metrics

The full metric list (including `scheduler_db_pool_*` and the in-flight gauge) and the alert rules are in [system-design.md → Observability](system-design.md#observability).

Backend exposes `/metrics`: `scheduler_http_requests_total`, `scheduler_http_request_duration_seconds`, `scheduler_bookings_total`, `scheduler_ws_clients`, `scheduler_queue_rows` (refreshed at most every 15 s), `scheduler_dependency_up{dep}` (Postgres / Redis reachable; all labeled by `instance_id`). Prometheus scrapes each backend directly; the gateway only proxies `/api/` (anything else, `/metrics` included, is 404, except the gateway's own `/gateway-health` liveness probe).

## Client IP and rate limits

Client IP (login/register rate limits): the browser-facing Nginx (web UI, and the gateway's public listener: container port 80, published on the host as `GATEWAY_PORT`, default 8080) overwrites `X-Forwarded-For` / `X-Real-IP` with the TCP peer, so clients cannot pick their own bucket; the UI's Nginx forwards to the gateway's internal container port 8080 (not published on the host), which is the only place a forwarded `X-Real-IP` is believed. Backends believe forwarding headers only from `TRUSTED_PROXIES` (compose: the gateway's fixed address `SCHEDULER_GATEWAY_IP`; `go run`: loopback), and the gateway's port 8080 answers only the web UI's fixed address (`SCHEDULER_WEB_IP`), so no other container and no host connection through a published port can choose its rate-limit bucket. Change `SCHEDULER_SUBNET` together with `SCHEDULER_DYNAMIC_RANGE`, `SCHEDULER_GATEWAY_IP` and `SCHEDULER_WEB_IP` (all inside the new subnet, the two IPs below the dynamic range) if `172.28.50.0/24` collides with a local network. Both proxies forward `Host` with its port, so the WebSocket same-origin check works on any port; set `ALLOWED_ORIGINS` to allow a UI on another origin. `INSTANCE_ID` names the replica in logs, metrics and the `X-Instance-ID` header (compose: `backend-1`/`backend-2`; unset: the hostname); every boot gets its own WebSocket fan-out consumer group regardless. Each backend creates the Kafka topic at startup if missing (`KAFKA_TOPIC_PARTITIONS`, default 3; `KAFKA_TOPIC_REPLICATION`, default 1; compose passes only the partition count through) — compose disables broker auto-creation, as production should — and consumers rebalance when partitions are added.

## Compression and caching

The backends compress API responses of 1 KiB or more per `Accept-Encoding` (zstd preferred, then gzip; `Vary: Accept-Encoding`) and keep the strong `ETag: "<version>"`, so it works unchanged as `If-Match`. `/api/v1/auth/*` (bodies carry tokens: BREACH), `/api/v1/ws/` and `/metrics` are never compressed. This runs in the backend (`httpapi/compress.go`), not the gateway, because nginx weakens an ETag when it compresses. The web UI's Nginx serves the SPA's assets gzipped at build time (`gzip -9` in `web/Dockerfile`, `gzip_static`), gzips other css/js/svg on the fly, caches the content-hashed `/assets/` for a year (`immutable`, on success only), and sends `index.html` with `Cache-Control: no-cache` so a deploy reaches open browsers on their next load.

## Web UI and auth sessions

UI: login / register / logout. Register creates a **customer** account linked to its own customer record; customers add their own vehicles and only ever see their own vehicles and appointments; staff pick a vehicle by searching its VIN, make, model, or owner (`GET /api/v1/vehicles?q=` returns one page, never the whole group). The day board and workshop actions (check-in, start, complete, no-show, reinstate, extend, reassign, history) are staff-only, and staff only see their own dealership (the demo admin is group-wide); admins also manage weekday hours, closures, booking policy, and technician rosters (shifts, breaks, absences). An appointment can carry several services (job lines); "Suggested times" (customers: best fits first) and "Next available" (staff: earliest) offer a few starts spread over the coming days; customers get confirmation, change, and reminder notifications (logged, or POSTed to `NOTIFY_WEBHOOK_URL`). All business APIs require `Authorization: Bearer <token>`: a short-lived access token (`ACCESS_TOKEN_TTL`, default 15 min) that the web app keeps in memory only. Login also sets an `HttpOnly; SameSite=Strict` refresh cookie (`__Host-uss_refresh`: `Secure`, path `/`, no domain; `uss_refresh` on path `/api/v1/auth` without `Secure` when `AUTH_COOKIE_SECURE=false` — the plain-http local stack only; a request carrying it twice is refused) that `POST /api/v1/auth/refresh` (with `X-Requested-With: fetch`, same-origin) trades for a new access token, rotating the cookie on every use: a token is good for `SESSION_IDLE_TTL` (24 h), a session ends `SESSION_MAX_TTL` (7 days) after login however often it is refreshed, and a rotated token presented again after a 60 s grace (two racing tabs, a lost response) counts as theft and revokes every session of the user (an expired one is only refused). A new login on the browser revokes its previous session, whose access tokens and sockets then stop too. Login and register take `Content-Type: application/json` only, and auth writes refuse `Sec-Fetch-Site: cross-site`. `POST /api/v1/auth/logout` (Bearer or cookie) signs the user out on every tab and device; mutations accept `If-Match: "<version>"` (412 when someone else changed the record first).

## WebSocket endpoint

`GET /api/v1/ws/dispatch?ticket=…` — WebSocket endpoint (gateway upgrades and load-balances). Browsers get a single-use 60 s ticket from `POST /api/v1/auth/ws-ticket` (redeemed in Redis; if Redis is down it stays reusable until it expires). Staff receive appointment notices for the dealership they follow, a customer receives their own, other customers only an anonymous `AVAILABILITY_CHANGED`; nobody receives names or VINs over the socket. Clients ignore stale `version`s and refetch after reconnecting.
